# Реестр студентов

Демонстрационное SPA на **Angular 22 + NG-ZORRO**: список студентов с серверной фильтрацией и карточка студента с многосекционной формой.

Бэкенд имитируется HTTP-интерсептором: сервисы работают с `HttpClient`, как с настоящим REST API. Данные вымышленные и хранятся в `localStorage`. Кнопка «Сбросить демо» возвращает исходный набор.

**Демо:** https://milamichailova.github.io/student-registry/

## Запуск

Нужен Node.js 22+.

```bash
npm install
npm start          # http://localhost:4200
npm run build      # production-сборка в dist/
```

### Публикация

GitHub Actions (`.github/workflows/deploy.yml`) при каждом push в `main`:

1. собирает приложение под адрес `/student-registry/`;
2. копирует `index.html` в `404.html`, чтобы прямые ссылки на маршруты открывались;
3. выкладывает сборку на GitHub Pages.

## Что показано

### Реактивные формы — все виды вложенности

| Где                                   | Структура                                                                     | Файл                          |
| ------------------------------------- | ----------------------------------------------------------------------------- | ----------------------------- |
| Основная информация, контакты, навыки | `FormGroup` плоских `FormControl`                                             | `student-form-base.ts`        |
| Языки                                 | `FormArray<FormGroup>` — повторяемые группы                                   | `student-languages-section`   |
| Личные качества                       | `FormArray<FormControl>` — список строк, каждая обязательна                   | `student-soft-skills-section` |
| Учебные проекты                       | `FormArray<FormGroup>`, внутри каждой группы ещё два `FormArray<FormControl>` | `student-projects-section`    |

- **Типизированные формы**: все типы групп описаны в `student-forms.types.ts`, `NonNullableFormBuilder`.
- **Валидация**:
  - `required`, `email`;
  - `pattern`, который не даёт оставить курс «Не указан»;
  - собственный валидатор Telegram (`username`, `@username`, `https://t.me/…`) с понятным текстом ошибки;
  - дата рождения не в будущем: валидатор плюс `nzDisabledDate` в календаре;
  - групповой валидатор периода проекта: окончание не раньше начала; ошибка стоит на группе, а показывается у поля «по».
- **Одна форма на создание и редактирование**: абстрактный `StudentFormBase` + компоненты-секции.
  - Секция получает контролы через `input.required()`, раскрытие — через `model()` (`[(active)]`), события — через `output()`.
  - Секция сама не знает, где используется.
- **Enter не сохраняет карточку**: в длинной форме сохранение только кнопкой. Иначе Enter в date-picker отправлял форму раньше, чем введённая дата попадала в контрол.
- **UX при ошибках**: при сохранении секции с ошибками раскрываются автоматически, в проектах раскрывается именно проект с ошибкой, страница прокручивается к первому невалидному полю.
- **Drag-and-drop** (CDK): порядок проектов и пунктов внутри проекта меняется перетаскиванием. Состояние раскрытия хранится по ссылке на группу, а не по индексу, поэтому переживает перестановку.
- **Связанные поля**: основное направление подготовки автоматически убирается из дополнительных, и наоборот.
- **Справочник** загружается один раз (`shareReplay`) и переиспользуется. Неудачная загрузка не кэшируется, в форме есть кнопка «Повторить».
- **Маппинг** форма ↔ API:
  - строки тегов через запятую превращаются в массивы;
  - пустые элементы массивов отбрасываются;
  - календарные даты передаются как UTC-полночь, без сдвига часового пояса.

### Защита несохранённых изменений

- `CanDeactivate`-guard с собственной модалкой: переход разрешает только явное «Не сохранять».
- `beforeunload` при закрытии вкладки.
- Сравнение со снимком формы после загрузки и после сохранения.

### Список

- Серверные поиск (с debounce), фильтры, сортировка и пагинация. Смена фильтра или сортировки возвращает на первую страницу.
- Адаптивность: уже 768px (`BreakpointObserver`) второстепенные колонки скрываются, группа, курс и статус показываются подписью под ФИО, без горизонтальной прокрутки.
- Запросы идут через `Subject` + `switchMap`, поэтому ответ на устаревший фильтр не перетирает новый.
- Удаление с подтверждением. Строка блокируется на время запроса, после удаления последней строки на странице список переходит на предыдущую.
- Поповер с краткой карточкой: данные догружаются при открытии, контакты копируются в буфер.
- Пустые состояния: «никого не найдено» с кнопкой сброса фильтров и «список пуст». Во время загрузки ни то, ни другое не показывается.

### Тема и дизайн-токены

- **Один источник цветов бренда**: `src/app/theme.ts`.
  - `provideNzConfig({ theme })` передаёт их в NG-ZORRO, собранный в режиме CSS-переменных (`ng-zorro-antd.variable.less`).
  - Оттенки hover/active библиотека вычисляет сама.
- **Токены приложения** в `src/styles/_tokens.scss`: поверхности, текст, рамки, состояния, радиусы, тени.
  - Основной цвет берётся из `--ant-primary-color`, а не дублируется.
  - Компоненты используют только токены, «сырых» цветов в их стилях нет.
- **Доступность**: у голубого `#25a1f4` на белом фоне контраст 2,8:1, этого мало для текста (WCAG AA — 4,5:1). Поэтому для ссылок и текстовых акцентов отдельный токен `--app-accent-text` (`#056ba7`, 5,7:1).

- **Скругления** задаются в `src/styles/ng-zorro-theme.less`.
  - Готовый CSS NG-ZORRO содержит жёсткие `2px`, поэтому библиотека собирается из Less-исходников.
  - Значения `@app-radius` (10px), `@app-radius-sm` (4px) и `@app-radius-lg` (16px) передаются в переменные NG-ZORRO (поля, кнопки, карточки, модалки).
  - Те же значения выводятся в CSS-переменные `--app-radius*` для собственных стилей.
  - Таблица оформлена карточкой на уровне темы: NG-ZORRO скругляет только верхние углы шапки, а рамка, нижние углы и тень добавлены через `@{table-prefix-cls}`, без правок в компонентах.

Сменить палитру или геометрию — поменять значения в `theme.ts`, `_tokens.scss` и `ng-zorro-theme.less`, компоненты трогать не нужно.

### Прочее

- Standalone-компоненты, ленивые маршруты, привязка параметров маршрута к `input()`.
- Сигналы для состояния, приложение без zone.js.
- Строгий TypeScript и `strictTemplates`.
- Всё, что относится к демо (имитация API, демо-данные, кнопка «Сбросить демо»), лежит в `mock-backend/`. Фича «студенты» о подмене бэкенда не знает.

## Структура

```text
src/app/
├── mock-backend/            имитация REST API, демо-данные, кнопка «Сбросить демо»
├── shared/
│   ├── forms/               guard и модалка несохранённых изменений
│   └── utils/               календарные даты, валидаторы Telegram и дат
└── students/
    ├── api/                 HTTP-сервисы: студенты, справочник направлений
    ├── student-forms/       базовая форма, типы и секции
    ├── student-create/      создание
    ├── student-edit/        редактирование
    ├── student-list/        список
    └── student-short-info-popover/
```
